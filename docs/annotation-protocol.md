# 标注协议（Annotation Protocol）

本文件是鼠标点击 ground-truth 标注的**唯一权威口径**。`snap_v1` 吸附规则的参数只在本文件第 3 节定义一次，其余文档（`README.md`、`labels/README.md`）只引用、不复制。

> **冻结约束：** 改动第 3 节任一参数 = 全部录音重新标注。改动须升版本号（`snap_v1 → snap_v2`）并在此记录变更。

---

## 1. 事件语义（Event Semantics）

- **原子事件 = 一次物理点击**，以其 **down（按下）onset 为代表**。
- **切点 = down onset 样本。** 这是流水线最终要对齐的目标，也是评估唯一计分的对象。
- 一次物理点击含 **down（按下）+ up（抬起）两个瞬态，相隔约 60–150 ms**。
  - **down = 这对里的第一个瞬态**，通常更尖、更响（press）。
  - **up = 第二个瞬态**，通常更弱（release）。
- **up 不是切点、不是独立目标事件**，仅作次要标注，供 verify 阶段做"配对核验"。

---

## 2. onset 参考点 = 能量起跳点（不是峰值）

在 2–5 ms 的尖锐瞬态上，"onset 落在哪一个样本"本质是**约定**而非客观事实。本项目把这个约定定为：

> **onset = 能量起跳的第一个样本（瞬态的"脚点"），而非峰值。**

理由：切点口径 = 参考点口径 = 评估目标，三者完全一致——评估直接衡量最终要切的那个点。

**人不直接抠样本。** 人只做"这里有/没有一次点击"以及粗略定位（放到 ~1 ms 尺度即可）这类人类擅长的判断；精确到样本由第 3 节的**确定性吸附规则**统一完成。这样 ~2500 次点击的一致性才有保证，避免跨标注者 ±1–2 ms 的抖动污染误差分布。

---

## 3. 吸附规则 `snap_v1`（冻结，唯一真源）

把人工粗标记吸附到精确 onset 样本的确定性规则：

| 项 | 取值 |
| --- | --- |
| 输入 | `data/wav/<name>.wav`（48 kHz / mono / float32） |
| 高通 | Butterworth 4 阶，截止 **2000 Hz**，零相位 `filtfilt`（不引入延迟） |
| 包络 | **1 ms 窗（48 样本）** 的 RMS 包络（对 \|x\|） |
| 本底估计 | 粗标记**前 50–100 ms** 窗内包络的中位数（剔除瞬态本身） |
| onset 判定 | 在粗标记 **±10 ms** 内，包络**首次**超过 `本底 + 6 dB` 的样本 |

**版本串（随结果一并报告）：** `snap_v1: HP2k / env1ms / +6dB / win±10ms`

### 3.1 开标前必做的两条护栏

1. **先验证再开标。** 在约 30–50 个点击上人工目检吸附是否落在真正的"脚点"，**重点查低 SNR 文件（`BJ_C1` / `IntlSB20`）**：`+6 dB` 是否会吸到 7–10 ms 周期干扰、或提前/滞后起跳。不通过就先调规则（并升版本号）。
2. **报告口径不确定度 + 防循环评估。**
   - **敏感性检查：** 同一批点击把阈值从 `+6 dB` 换成 `+10 dB`，记录 GT 中位数移动了多少 ms，作为"口径不确定度"随评估结果一起报告。
   - **防循环：** 若流水线 step 6（backtrack）复用与 `snap_v1` **相同**的逻辑，eval 测出的"精度"只反映检测 + 峰拾取，backtrack 本身好坏被定义掉。对策：让二者逻辑独立；若无法独立，须在结果中明确标注其同源、精度数仅反映"检测 + 峰拾取"。

## 4. CSV 标注格式

- **每个 WAV 一个文件：** `labels/<wav_basename>.csv`，与 `data/wav/<name>.wav` 同名配对（如 `labels/BJ_C1.csv` ↔ `data/wav/BJ_C1.wav`）。
- **坐标系 = 解码后 WAV 的样本帧，不是 m4a。**（m4a 有 priming delay；标注、检测、切割都在同一份 WAV 上做，坐标才一致。）
- 含表头，UTF-8，按 `sample` 升序。

```
sample,time_s,type,confidence
12345,0.257188,down,确定
19632,0.409000,up,存疑
```

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `sample` | int | WAV 样本索引 @48 kHz——**真源**（整数无舍入） |
| `time_s` | float（6 位小数） | `= sample / 48000`，给 `mir_eval` 用 |
| `type` | `down` \| `up` | 瞬态类型 |
| `confidence` | `确定` \| `存疑` | 标注把握度 |

---

## 5. down / up 指派与边界规则

- 一对点击 = 相隔 **60–150 ms** 的两个瞬态：**第一个 = down，第二个 = up**。
- **up 尽力而为：** 仅在能清晰辨认时标；不确定标 `存疑`；看不见就**留空不标**。
- **7–10 ms 周期性脉冲串 = 环境干扰，绝不标注。** 标注时显式排除该区段（量化结果见 `src/interference_analysis.py`：`IntlSB20` 最重，约占 8% 时长）。
- **点击间距：** click-to-click（down→down）`min_gap` 约 30–50 ms 安全。注意一对内 down→up 仅相隔 60–150 ms——峰拾取的 `min_gap` 不可大到把同一对的 down/up 误并（属 step 4 峰拾取的设计注记，与标注无关，此处仅备忘）。

---

## 6. verify 阶段的配对核验（设计注记）

- 对每个 down，向后 **60–150 ms** 找 up：**找到加分、找不到不扣分。** up 缺失绝不否决 down，因此 up 标注的不完整不会污染评估。
- 先在 `BJ_C3` 上统计 up 的可辨率，再据此确定该规则在 verify 中的权重。

---

## 7. 标注工作流

1. 用现有粗检测导出候选 → 转成标注工具可导入的 label 文件作为**种子**。
2. **工具：** 默认 **Sonic Visualiser**（样本级缩放、CSV 导出）；更熟 Audacity 亦可——亚毫秒精度由 `snap_v1` 保证，工具差异不重要，选顺手的即可。
3. 人工逐个**确认 / 增删 / 粗调**（放到 ~1 ms 尺度即可，不必抠样本）。
4. 跑 `snap_v1` 把每个粗标记吸附到精确样本，产出最终 `labels/<name>.csv`。
5. up 同法、尽力而为。

---

## 8. 评估口径联动

`mir_eval.onset` 对比 GT 与检测输出：

- 报告**误差分布**（中位数、p95，单位 ms）；
- 报告**紧容差下的 F-measure**（如 5 ms / 10 ms）；
- 一并报告第 3.1 节的**口径不确定度**与 `snap_v1` 版本串。
- **只有 `down` 行参与 onset 评估；`up` 仅供 verify 核验。**
